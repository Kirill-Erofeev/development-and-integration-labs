## Автоматические тесты без сети

Из корня рабочего проекта выполнено:

```powershell
$env:PYTEST_DISABLE_PLUGIN_AUTOLOAD = '1'
$env:PYTHONDONTWRITEBYTECODE = '1'
py -3.11 -B -m pytest -q -p no:cacheprovider scripts/tests client/tests
```

Фактический вывод:

```text
........................................                                 [100%]
40 passed in 1.33s
```

Девять сценариев проверяют команду `check_api.py`, 31 — клиент. Проверены
успешные ответы, неготовая модель, некорректные типы/классы, HTTP-ошибки,
перенаправления, повреждённый JSON, тайм-аут, настройки окружения и ошибки записи.
При ошибке предыдущий результат сохраняется; временный файл очищается.
Все HTTP-вызовы заменены имитациями. Модель и датасеты не загружались.

## Статическая проверка и healthcheck

- `compose.yaml` разобран установленным PyYAML; сверены пути, сеть, переменные,
  зависимость готовности, лимиты и каталог результата.
- Проверены пути `COPY` обоих Dockerfile и наличие явно разрешённых файлов.
  Байты модели и исключённых учебных данных не читались.
- Разобраны AST четырёх новых Python-файлов: два исполняемых модуля и их тесты.
- Python-команда healthcheck из Compose выполнена с имитацией HTTP:
  семь сценариев подтвердили успех только при `status=ok` и `model_ready=true`,
  отказ при неготовности, неверном статусе и ошибках обращения.
- По установленным метаданным проверены версии и замыкание зависимостей
  для Linux/Python 3.11: 25 пакетов API и 5 пакетов клиента. 
- Десять блоков команд PowerShell в инструкциях практик разобраны без исполнения;
  ошибок синтаксиса нет. Относительные ссылки проверены для конечных путей.
- Независимый статический review конфигурации и клиента существенных дефектов
  не обнаружил.
