### Окружение и запуск CLI

Все команды выполняются из корня репозитория в PowerShell.
Используется глобальный Python 3.11 без `.venv`.
Исходный эксперимент проверен на Python 3.11.9.

```powershell
py -3.11 -m pip install -r requirements.txt
py -3.11 src/train.py
py -3.11 src/predict.py
py -3.11 src/predict.py --output-format text
py -3.11 -m pytest
```

Обучение нужно для восстановления или обновления артефакта; при наличии
готового `models/model.pkl` предсказание и API запускаются без этого шага.
Версии зависимостей закреплены в [requirements.txt](requirements.txt),
включая библиотеки модели, FastAPI, Pydantic, Uvicorn, pytest и HTTPX.
`scikit-learn==1.7.2` и `joblib==1.5.2` сохранены из заготовки.

Поддерживается запуск как модулей: `py -3.11 -m src.train`
и `py -3.11 -m src.predict`. На POSIX аналогичные команды используют
`python3.11`; запуск на Linux и установка в чистое окружение не проверялись.

### Вход CLI, артефакт и результат

CLI принимает CSV в UTF-8 с разделителем-запятой и четырьмя уникальными
колонками: `sepal_length`, `sepal_width`, `petal_length`, `petal_width`.
Колонки можно переставлять; скрипт восстановит порядок признаков модели.
Допускаются несколько объектов и завершающие пустые строки.
Каждый объект должен содержать четыре конечных числовых значения.
Пустой набор, пропуски, лишние или повторяющиеся колонки, нечисловые значения,
`NaN` и бесконечности отклоняются.

`train.py` загружает Iris, выполняет стратифицированное разделение,
обучает `LogisticRegression` и сохраняет через `joblib` словарь:

- `model` — обученный классификатор;
- `feature_columns` — список признаков в порядке обучения;
- `target_names` — список имён классов.

Исходный notebook сохраняет только классификатор. Для итоговых CLI и API
артефакт следует создавать через `train.py`.
Общий `ModelService` проверяет формат артефакта и порядок признаков,
получает классы и их имена без повторного `fit` и без загрузки Iris.

Формат вывода `predict.py`: JSON по умолчанию; `--output-format text` включает текстовый вывод.
Результаты направляются в stdout, диагностика ошибок — в stderr.
В JSON возвращается список, по одному объекту на входную строку,
с полями `predicted_class` (целое число) и `predicted_name` (строка).
В текстовом формате каждому объекту соответствует строка
`predicted_class=0 predicted_name=setosa`. Порядок объектов сохраняется.
Неизвестный формат отклоняется с кодом `2` до загрузки модели.
Ошибки входных данных, отсутствующих файлов и неподходящего формата артефакта
сообщаются в stderr с кодом завершения `2`, без traceback.

### HTTP API

```powershell
py -3.11 -m uvicorn app.api:app --host 127.0.0.1 --port 8000
```

В другом терминале PowerShell проверьте готовность и отправьте искусственный
пример с четырьмя признаками:

```powershell
Invoke-RestMethod -Uri http://127.0.0.1:8000/health | ConvertTo-Json
$irisRequest = @{
    sepal_length = 5.1
    sepal_width = 3.5
    petal_length = 1.4
    petal_width = 0.2
} | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/predict `
    -ContentType 'application/json' -Body $irisRequest | ConvertTo-Json
```

Ожидаемый ответ `/health` — `{"status":"ok","model_ready":true}`.
Для приведённого примера с сохранённой моделью Iris ожидается:

```json
{"prediction": 0, "class_name": "setosa"}
```

| Маршрут | Контракт |
| --- | --- |
| `GET /health` | Состояние сервиса и готовность загруженной модели |
| `POST /predict` | Один объект из четырёх признаков → `prediction: int`, `class_name: str` |
| `GET /docs` | Swagger UI |
| `GET /openapi.json` | Машиночитаемое описание маршрутов и схем |
| `GET /redoc` | Дополнительное представление документации |

Откройте `http://127.0.0.1:8000/docs` и
`http://127.0.0.1:8000/openapi.json`.
Схемы запроса, ответа и готовности заданы в `app/schemas.py`.
API принимает только числовые значения JSON: целые и дробные, строго больше
нуля и конечные. Строки с числами, логические значения, пропущенные и лишние
поля, `null`, `NaN` и бесконечности отклоняются с кодом `422`.
Некорректный JSON также возвращает `422`.
Поле `detail` содержит массив ошибок с `loc`, `msg` и `type`.

API обрабатывает один объект и возвращает один JSON-объект; CLI обрабатывает
строки CSV и возвращает JSON-список либо текст. API дополнительно требует
положительности признаков; CSV-интерфейс проверяет их конечность.

`create_app(model_path=None)` выбирает путь при создании приложения:
явный аргумент → переменная окружения `ML_MODEL_PATH` → `models/model.pkl`
относительно файлов проекта. Относительный путь из аргумента или переменной
окружения отсчитывается от каталога запуска. Переменную задают до старта Uvicorn:

```powershell
$env:ML_MODEL_PATH = (Resolve-Path .\models\model.pkl).Path
```

Импорт `app.api` не загружает артефакт. `lifespan` загружает модель один раз
на процесс приложения; запросы используют тот же `ModelService`.
Отсутствующий или неподходящий артефакт вызывает понятную ошибку старта.
HTTP-интерфейс не обучает модель и не принимает путь к ней из запроса.
Остановка сервера — `Ctrl+C`.

### Автоматические проверки

```powershell
py -3.11 -m pytest
py -3.11 -m pytest tests/test_api.py
```

Исходные проверки охватывают обучение, артефакт, предсказание, ошибочные CSV
и CLI из другого каталога. Дополнительные тесты проверяют форматы CLI,
валидацию артефакта, HTTP-схемы, ошибки запросов, выбор модели через аргумент
и окружение, единственную загрузку, отсутствие обучения и документацию.
API проверяется через `TestClient` без запуска внешнего HTTP-сервера.
Для независимых сценариев используются синтетические артефакты;
отдельный тест проверяет сохранённую модель Iris из репозитория.
Актуальные результаты практик 2–4 фиксируются в записях соответствующих работ.
Итоговый прогон 18 сентября 2026 года: **55 passed in 8.98s**.
Сервис также прошёл восемь проверок через отдельный процесс Uvicorn.

### Ограничения

Модель учебная; точность относится к выбранному разделению Iris.
Проверки окружения ограничены глобальным Python по принятому решению;
чистое окружение для этой работы не создаётся.
Через `joblib` следует загружать только собственный или доверенный артефакт
с теми же версиями зависимостей, что использовались при обучении.
Причины — возможность выполнения кода при загрузке и отсутствие гарантии
совместимости между версиями; см. [документацию scikit-learn 1.7](https://scikit-learn.org/1.7/model_persistence.html)
(сверено 11 сентября 2026 года).
