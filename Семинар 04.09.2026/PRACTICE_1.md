# Практика 1 — структура ML-проекта

## Требование и реализация

Исследовательский notebook сохранён в `Семинар 04.09.2026/notebooks/`.
Его обучение перенесено в `src/train.py`, чтение входа и инференс — в
`src/predict.py`, порядок признаков и пути — в `src/common.py`.
Команды разделены: обучение создаёт артефакт, прогноз загружает его без `fit`.

Параметры эксперимента: Iris, стратифицированный `train_test_split`,
`test_size=0.25`, `random_state=42`; `LogisticRegression(max_iter=300, random_state=42)`.
Ожидаемая accuracy исходного разбиения — `0.9473684210526315` (CLI печатает `0.947`).
Это результат одного контрольного разбиения, а не оценка качества для любых данных.

## Запуск и воспроизведение

Из корня, глобальный Python 3.11:

```powershell
py -3.11 -m pip install -r requirements.txt
py -3.11 scripts/check_notebook.py --notebook "Семинар 04.09.2026/notebooks/source_experiment.ipynb" --input data_sample/sample.csv --work-dir .verification/notebook-run --reference-model models/model.pkl
py -3.11 src/train.py --model-path .verification/training/model.pkl
py -3.11 src/predict.py --model-path .verification/training/model.pkl
py -3.11 -m pytest -q
```

Helper выполняет ровно пять предварительно проверенных ячеек. Он копирует только
разрешённый `sample.csv` в новый каталог `.verification/` и сохраняет там модель
notebook; существующий каталог не перезаписывается. Рабочие `models/model.pkl`
и входной файл не заменяются. Подробности — [CHECK_NOTEBOOK.md](../scripts/CHECK_NOTEBOOK.md).
При повторе задайте новое имя каталога проверки.

Notebook сохраняет сам estimator, а модуль обучения — словарь
`model`, `feature_columns`, `target_names`. Сравнение должно подтверждать одинаковые
коэффициенты, intercept, классы и порядок признаков, а не совпадение байтов разных упаковок.

CLI принимает UTF-8 CSV с четырьмя уникальными колонками
`sepal_length`, `sepal_width`, `petal_length`, `petal_width` в любом порядке.
Числа должны быть конечными; пустой ввод, пропуски, лишние/повторные колонки и
нечисловые значения отклоняются. JSON-ответ контрольного примера:
`[{"predicted_class":0,"predicted_name":"setosa"}]`.

## Критерии проверки

1. Выполнить notebook, сравнить модель и получить ожидаемые accuracy/прогноз.
2. Отдельно выполнить обучение, инференс и полный pytest.
3. Проверить команды из чистого клона конкретного нового коммита, затем записать
   точные команды и результаты. Наличие `.git` и сохранённого артефакта само по себе
   не доказывает воспроизводимость.
4. Проверить запуск CLI с абсолютным путём из другого каталога; стандартные пути
   должны определяться от проекта.
