# Вариант 4 — паспорт модели и идентификатор запроса

## Цель

Добавить наблюдаемость на уровне контракта: клиент должен видеть паспорт загруженной модели, а каждый прогноз — иметь идентификатор запроса, пригодный для поиска в логах.

## Материалы

- `notebooks/source_experiment_updated.ipynb` извлекает метаданные модели без повторного обучения;
- `notebooks/new_functionality.ipynb` создаёт и проверяет UUID request ID, а также формирует безопасную запись события прогноза.

Модель загружается один раз при старте/первом обращении. Не возвращайте сериализованный объект модели, путь на диске или персональные данные. Для каждого `POST /predict` используйте заголовок клиента `X-Request-ID`, если он содержит корректный UUID; иначе создайте UUID на сервере. Тот же идентификатор должен быть в ответе и структурированной записи лога.

## Контракт API

| Метод и путь | Назначение | Успешный результат |
|---|---|---|
| `POST /predict` | Прогноз с идентификатором запроса | `class_id`, `class_name`, `request_id` |
| `GET /model-info` | Безопасный паспорт модели | `model_type`, `classes`, `feature_count`, `model_loaded` |
| `GET /health` | Готовность сервиса и модели | `status: "ok"`, `model_loaded` |

При некорректном `X-Request-ID` выберите и опишите единое поведение: либо 400, либо генерация нового UUID с указанием этого в документации. Проверяйте запросы модели и не выдавайте технические traceback'и клиенту.

## Фронтенд

Страница загружает `/model-info`, выводит паспорт модели и запрашивает `/health` для индикатора состояния. После отправки формы она создаёт UUID через `crypto.randomUUID()`, передаёт его в `X-Request-ID` запросом `fetch('/predict')`, а затем показывает класс и возвращённый request ID. Так студент видит связь браузерского действия, HTTP-запроса, ответа и серверного лога.

Статический файл должен отдаваться тем же приложением по `GET /`. В README опишите, какие сведения допустимо раскрывать через `/model-info`, а какие (например, путь к файлу модели) — нет.

## Проверки

Добавьте не менее пяти тестов: состав паспорта модели, генерация/передача request ID, неверный UUID согласно выбранному контракту, успешный прогноз, `/health` и HTML-ответ `/`.
