## Как связаны коммиты и доказательства

Для каждого этапа сначала фиксируются код и тесты. Затем на чистом отслеживаемом дереве выполняются проверки и захват изображений. Записи `verified_sha` и `verified_worktree_sha` указывают на проверенный коммит; сами журналы, метаданные и PNG добавляются следующим коммитом. После этого начинается следующий этап. Поэтому проверенный SHA является предком коммита с доказательствами и итоговой истории, а не обязан совпадать с последним `HEAD`.

Для ожидаемого конфликта практики 2 допускается `verified_sha: null`: конфликт намеренно изменяет состояние индекса. Такой прогон должен быть явно обозначен `expected_failure`. Ожидаемый ненулевой код примера с `localhost` также не означает провал всей практики.

Готовые Word-отчёты пользователь оформляет после вставки изображений. Каждый законченный отчёт добавляется отдельным завершающим коммитом поверх готовой истории. Старые коммиты с кодом и доказательствами не переписываются; публикация отчётов не требует пересоздания старых снимков.

## Время и SHA запусков GitHub

В измерении 04.10.2026 заголовок `Date` GitHub API показал `19:07:45 GMT`, когда локальные часы показывали `22:02:28 +03:00` (`19:02:28 UTC`). В этом замере удалённые часы опережали локальные примерно на **5 минут 17 секунд**. Это наблюдение конкретного прогона, не постоянная поправка. Исходные временные отметки карточек, manifest и GitHub-журналов сохранены без выравнивания; пояснение присутствует на обновлённых снимках практики 7. Данные измерения находятся рядом с её доказательствами в `clock-comparison.json`.

В workflow события `pull_request` значение `GITHUB_SHA` соответствует временному коммиту слияния PR, а `github.event.pull_request.head.sha` — голове исходной ветки. Поэтому SHA в Docker-теге, сформированном из `github.sha`, может отличаться от SHA головы PR, указанного API. Соответствие проверяют по событию, run ID и этим двум ролям SHA. Официальное описание проверено 04.10.2026: [GitHub Actions — pull_request](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request).
