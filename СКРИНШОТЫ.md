## Общий каталог повторного прогона

Общий рабочий каталог перенесён в корневую папку проекта `.verification/course-20261005/`. Проверочный Git checkout расположен в `.verification/course-20261005/history-draft`, а вспомогательные инструменты — рядом с ним. Корень Git и рабочие каталоги команд записываются при новых фактических запусках. Журналы, HTML-карточки и PNG каждого этапа сохраняются в папках соответствующих занятий внутри этого checkout. Перенос подтверждается отдельным аудитом путей перед финализацией и установкой истории.

## Как связаны коммиты и доказательства

Для каждого этапа сначала фиксируются код и тесты. Затем на чистом отслеживаемом дереве выполняются проверки и захват изображений. Записи `verified_sha` и `verified_worktree_sha` указывают на проверенный коммит; сами журналы, метаданные и PNG добавляются следующим коммитом. После этого начинается следующий этап. Поэтому проверенный SHA является предком коммита с доказательствами и итоговой истории, а не обязан совпадать с последним `HEAD`.

Для ожидаемого конфликта практики 2 допускается `verified_sha: null`: конфликт намеренно изменяет состояние индекса. Такой прогон должен быть явно обозначен `expected_failure`. Ожидаемый ненулевой код примера с `localhost` также не означает провал всей практики.

Готовые Word-отчёты пользователь оформляет после вставки изображений. Каждый законченный отчёт добавляется отдельным завершающим коммитом поверх готовой истории. Старые коммиты с кодом и доказательствами не переписываются; публикация отчётов не требует пересоздания старых снимков.

## Время и SHA запусков GitHub

Временные отметки ноутбука и GitHub относятся к независимым часам. В карточках, манифестах и журналах сохраняются исходные значения с их часовыми поясами; ручная поправка и подгонка времени не применяются. Порядок выполнения подтверждают связи коммитов, идентификаторы запусков и записи фактических проверок. Численная разница часов для этого прогона отдельно не измерялась.

В workflow события `pull_request` значение `GITHUB_SHA` соответствует временному коммиту слияния PR, а `github.event.pull_request.head.sha` — голове исходной ветки. Поэтому SHA в Docker-теге, сформированном из `github.sha`, может отличаться от SHA головы PR, указанного API. Соответствие проверяют по событию, run ID и этим двум ролям SHA. Описание ролей SHA: [GitHub Actions — pull_request](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#pull_request).
